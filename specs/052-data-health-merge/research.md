# Research: صحة البيانات — اكتشاف ودمج المكرّر

## D1 — الدمج على الجهاز بالمزامنة العادية، مش SQL على السيرفر
- **Decision**: التنفيذ على قاعدة المالك المحلية ثم طابور مزامنة (تحديث/حذف)، زي `deleteRecordsInRange` و`deleteStudent`.
- **Rationale**: المسار ده بيحترم حرّاس صلاحيات الحذف على السيرفر (المالك مصرّح)، وبيوصل للمساعد تلقائيًا، وما فيش تعطيل triggers ولا أي وصول إدارة. (محاولة سكربت السيرفر وقفت عند `check_delete_*` وفتحت مشكلة صلاحيات.)
- **Alternatives**: Edge function/RPC على السيرفر للدمج — مسار جديد للأمان والصيانة وبيعوّد المدرس على الاعتماد على السيرفر؛ سكربت أدمن — اللي بنتفاداه.

## D2 — حذف الصفوف المكرّرة صراحةً قبل حذف الطالب
- **Decision**: نجمّع (جدول، pk، remote_id) للصفوف المكرّرة ونطابر `_queueDelete` لها، ثم نحذف الطالب (الـCASCADE المحلي بيشيل أطفاله).
- **Rationale**: الـCASCADE المحلي ما بيطابرش حذف للمزامنة؛ `deleteStudent` الحالي بيعمل نفس النمط (collect → حذف → queue).

## D3 — ترتيب الطابور: نقل ← حذف مكرّر ← حذف طالب ← حذف مجموعة
- **Decision**: نطابر أولًا `update` للصفوف المنقولة (بـ`_queueRowUpsert`، payload كامل)، بعدها حذف الصفوف المكرّرة، ثم الطلاب، ثم المجموعة.
- **Rationale**: الـoutbox FIFO؛ المساعد بيستقبل بنفس الترتيب. الـpush بيحوّل `student_id` المحلي لـ`student_remote_id` الأساسي ويتخطّى الصف لو الأساسي بلا remote id — فالشرط المسبق مهم.

## D4 — شرط: الأساسي متزامن + outbox فاضي (أو تحذير)
- **Decision**: في وضع الفريق، التنفيذ يتطلب إن الأساسي له `remote_id`؛ وعدّاد صفوف `sync_outbox` المعلّقة > 0 يظهر تحذير مع خيار "استنّى" أو "كمّل".
- **Rationale**: بيمنع طابور فيه نقل لطالب لسه مش على السيرفر، وبيقلّل تضارب LWW مع تعديلات معلّقة.

## D5 — نواة صرفة للاكتشاف والخطة
- **Decision**: `duplicate_detection.dart` (تطبيع + مجموعات + طلاب + أساسي مقترح) و`merge_plan.dart` (خطة من مدخلات بسيطة: للطالب المكرّر، قوائم مفاتيح الصفوف عند الأساسي وعند المكرّر).
- **Rationale**: بيتختبر بدون DB (نمط المشروع)، ونفس الدالة بتغذّي المعاينة والتنفيذ (تماثل 100%).
- **Alternatives**: كل المنطق في SQL (join/group by) — صعب الاختبار وصعب عرض التفاصيل للمدرس.

## D6 — الاكتشاف بالتطبيع (بدون fuzzy)
- **Decision**: نفس `normalizeArabic` المضافة في spec 051 (تُنقل لـutil مشترك أو تُستورد) + trim/collapse spaces + lowercase. التطابق: كود مطابق (case-insensitive، اللاحقة `-N` بتتشال للمقارنة فقط) أو اسم مطبّع داخل نفس المجموعة/المجموعتين المكرّرتين.
- **Rationale**: بيغطي حالات الواقع (G206 / G206-2) بلا إيجابيات كاذبة كتير؛ التطابق بالاسم فقط بيتطلّب قرار صريح.

## D7 — الإخوة ≠ تكرار
- **Decision**: طالبين بنفس رقم ولي الأمر وأسماء مختلفة (أو في نفس `sibling_group`) مش بيتحسبوا تكرار؛ التطابق الاسمي بيستلزم نفس الاسم المطبّع كامل.
- **Rationale**: الإخوة بيشاركوا رقم ولي الأمر وأحيانًا الأسماء متشابهة جزئيًا.

## D8 — النسخة الاحتياطية = الاسترجاع المضمون
- **Decision**: `BackupService().createBackup()` قبل التنفيذ (نفس `DeleteRecordsController.runDelete`)، والاسترجاع من شاشة النسخ الموجودة. زر "تراجع" داخل الجلسة خارج النطاق (P3 اختياري).
- **Rationale**: الحذف المحلي فعلي (hard)؛ الـsoft على السيرفر وحده مش كفاية للمدرس.

## D9 — سجل العمليات محلي بسيط
- **Decision**: JSON في `settings` (آخر 20 عملية: وقت، أرقام، قائمة مدموجة مختصرة، مسار النسخة).
- **Rationale**: بلا جدول جديد ولا migration؛ التقرير للعرض والمشاركة بس.

## D10 — المراقبة والتقارب مع المساعد
- **Decision**: بعد الدمج نعرض للمالك "لازم المساعد يكون على 1.2.74+"؛ ونعتمد على حماية 049 (in-place update + `_noteIfSuffixed`) لمنع رجوع المكرّر.
- **Rationale**: النسخ الأقدم هي مصدر التكرار الأصلي.
