# Data Model: تعديل مجموعة الإخوة عند خروج عضو

## حقل جديد على الطالب (Student)

- **`siblingGroupCommittedCount`** (`int?`, عمود `sibling_group_committed_count`): عدد أعضاء مجموعة الإخوة النشطين وقت آخر قرار واعي (ربط أولي أو تأكيد/تعديل بعد خروج عضو). `null` لطالب مش في مجموعة إخوة أصلاً.
  - **يتحدّث فقط** عند: (أ) `linkSiblingGroup` الأولي — يُضبط = عدد الأعضاء وقت الربط. (ب) المدرس يأكّد/يعدّل المبلغ بعد تنبيه خروج عضو — يُضبط = العدد النشط الحالي.
  - **لا يتحدّث** تلقائيًا عند أي حذف/أرشفة — وده بالظبط اللي بيخلّي الفرق (لو حصل) قابل للاكتشاف.

## الحالة المحسوبة: "قرار معلّق"

مش كيان مخزَّن — دالة صرفة في `pricing_helper.dart`:

```
siblingGroupDepartureAlert(student, allStudents) →
  null                                    لو مش في مجموعة إخوة، أو العدد الحالي = committedCount
  DepartureAlert(oldCount, newCount)      لو العدد الحالي (siblingGroupSize) < committedCount المخزَّن
```

الفرق بين `oldCount` و`newCount` بيوضّح للمستخدم كام عضو خرج بالظبط (عادة ١).

## حالات الانتقال (State Transitions)

1. **مجموعة إخوة جديدة (٢ أو ٣)** → `committedCount = العدد الأولي` (بلا تنبيه، حالة مستقرة).
2. **عضو يخرج (حذف/أرشفة)** → `committedCount` يفضل زي ما هو (بلا تغيير) بينما العدد الفعلي (`siblingGroupSize`) بينزل → **تنبيه يظهر** لأي عضو فريق يفتح المجموعة/أحد الباقيين.
3. **المدرس يأكّد أو يعدّل** → `committedCount = العدد الفعلي الحالي` لكل الأعضاء الباقيين (+ `siblingsTotal` الجديد لو عدّل) → التنبيه يختفي (الحالة استقرّت تاني).
4. **عضو مؤرشف يتم استرجاعه قبل أي قرار** (FR-007) → العدد الفعلي يرجع يطابق `committedCount` تلقائيًا → التنبيه يختفي من غير أي تدخّل.
5. **المجموعة تنزل لعضو واحد بس** (خارج النطاق — FR-009): السلوك الحالي (`_unlinkOrphanedSiblingSurvivor`) يفضل زي ما هو، بلا تفاعل مع الحقل الجديد.

## أثر على حساب المديونية الفعلي (يحقق FR-004)

القاسم المستخدم في `monthlyDue` (`siblingsTotal / count`) لازم يبقى **`committedCount` المخزَّن**، مش `siblingGroupSize` الحي — ده اللي فعليًا بيمنع القفزة الصامتة، مش بس عرض تنبيه فوقه. `siblingGroupSize` (العدد الحي) يُستخدم فقط لاكتشاف الفرق (المقارنة في `siblingGroupDepartureAlert`)، مش كقاسم في أي حساب مالي فعلي، طول ما فيه قرار معلّق.

## بلا تغيير

- `siblingGroupId` (الرقم المحلي)، `siblingGroupUuid` (المزامنة عبر الأجهزة، spec 034)، `siblingsTotal` — بنفس المعنى والاستخدام الحاليين تمامًا.
