# Quickstart / Validation: حالة حضور "متأخر"

**Feature**: 011-late-attendance | نفس نهج التحقّق اليدوي في specs 009/010.

## المتطلبات المسبقة

- `flutter analyze` نضيف (صفر أخطاء جديدة).
- بناء debug/release على جهاز فيه بيانات حضور قديمة (للتحقّق من migration v20→v21).
- مجموعة تجريبية بجدول مواعيد + طلاب، وطالب واحد على الأقل له بوابة أولياء أمر مفعّلة.
- مجموعة تجريبية تانية **بدون** جدول مواعيد.

## سيناريوهات التحقّق

### 1. Migration + توافق تاريخي (FR-001، FR-014، SC-006)
1. ثبّت النسخة الجديدة فوق نسخة قديمة فيها سجلات حضور.
2. افتح تبويب الحضور وتفاصيل طالب — كل السجلات القديمة تظهر صح (حاضر/غائب) بلا انهيار.
3. من DB inspector (أو سجل): `PRAGMA table_info` / محاولة كتابة `'متأخر'` تنجح.

### 2. تسجيل "متأخر" بالـsegmented (US1 — FR-002)
1. افتح موديل مجموعة → تبويب "حضور".
2. لكل طالب 3 أزرار: حاضر / متأخر / غائب.
3. اضغط "متأخر" لطالب → يتحدّد وحده، لون كهرماني، يتحفظ فورًا.
4. اقفل الموديل وافتحه → لسه "متأخر".
5. اضغط "متأخر" تاني على نفس الطالب → يرجع "غير مسجّل".
6. اضغط "حاضر" ثم "متأخر" → ينتقل مباشرة بلا حالة وسيطة.

### 3. الزر الجماعي (US1 — FR-004)
1. سجّل طالب "متأخر" يدويًا، وسيب الباقي غير مسجّلين.
2. اضغط "الكل حاضر" / "تحضير الكل".
3. الباقي = "حاضر"، والطالب المتأخر **لسه "متأخر"** (ما اتكتبش فوقه).

### 4. QR auto-late (FR-005، FR-005a، FR-005b)
1. الإعدادات → "مهلة التأخير (دقائق)" = 15 (افتراضي ظاهر)، ومفتاح "تسجيل المتأخر تلقائيًا عبر QR" **مفعّل** (افتراضي).
2. المجموعة ذات الجدول: عدّل وقت بداية الحصة لـ20 دقيقة قبل الآن → امسح QR طالب → يتسجّل **"متأخر"** تلقائيًا.
3. عدّل البداية لـ5 دقائق قبل الآن → امسح طالب تاني → يتسجّل **"حاضر"**.
4. غيّر المهلة لـ30 → كرّر خطوة 2 (البداية 20 دقيقة قبل) → يتسجّل **"حاضر"** (لسه جوّه المهلة).
5. المجموعة **بدون** جدول نصّي: امسح طالب → يتسجّل **"حاضر"** دائمًا.
6. **أوقف** المفتاح → امسح طالب بعد المهلة بكتير → يتسجّل **"حاضر"** (السلوك القديم).
7. بعد تسجيل "متأخر" عبر QR: افتح الموديل وغيّرها يدويًا لـ"حاضر" → تتحدّث.

### 5. نسبة الحضور والإحصائيات (US2 — FR-006، FR-007، FR-013، SC-002)
1. مجموعة 10 طلاب: 6 حاضر + 2 متأخر + 2 غائب.
2. نسبة الحضور = **80%** (المتأخر محسوب حضور).
3. ملخّص الموديل يعرض "حاضر 6 · متأخر 2 · غائب 2".
4. تبويب الإحصائيات + الداشبورد: "متأخر" فئة ظاهرة منفصلة.
5. مجموعة "بالحصة": الطالب المتأخر **تتخصم عليه حصة كاملة** (نفس الحاضر) — تأكّد من المديونية/عدّاد الحصص.

### 6. تبويب "غياب اليوم" (US3 — FR-008، SC-004)
1. سجّل حالات مختلطة، افتح "غياب اليوم".
2. المتأخرون **مش** في قائمة الغياب.
3. تحت الغايبين: قسم "متأخرين" فيه المتأخرين.
4. يوم بلا متأخرين → القسم مخفي/هادئ، القائمة زي ما كانت.

### 7. تقارير الواتساب + PDF (US4 — FR-009..FR-012، SC-005)
1. سجّل "متأخر" لطالب له بوابة.
2. تقرير الحصة اليومي → الرسالة فيها حالة "⏰ متأخر" مميّزة.
3. التقرير الشهري → عدّاد "أيام تأخير" + سطر اليوم يعرض "متأخر".
4. تصدير تقرير الحضور PDF → خانة يوم المتأخر مميّزة + عدّاد منفصل.

### 8. بوابة أولياء الأمور (US4 — FR-011)
1. بعد تسجيل "متأخر"، افتح صفحة `active-class.online/track/{slug}` (بعد نشر VPS).
2. سجل الحضور + العدّادات يعرضوا "متأخر" كحالة ثالثة.

### 9. الربط بالواجب (SC-007 — spec 010)
1. طالب "متأخر" → تبويب "واجب": أزرار الواجب **تظهر له عادي** (مش زي الغائب).
2. طالب "غائب" → أزرار الواجب تختفي (سلوك spec 010، بلا تغيير).

### 10. اكتمال التسجيل
1. مجموعة كل طلابها حاضر/متأخر/غائب (مفيش "غير مسجّل") → تُعتبر "اكتمل تسجيلها".

## بوّابة القبول

كل السيناريوهات 1–10 تنجح + `flutter analyze` نضيف + جرد `rg "== ATTENDANCE_PRESENT"` كله
راجعناه وكل موضع "معناه حضر" اتحوّل لـ`attendanceCountsAsPresent`.
