# Data Model: إعادة هيكلة شاشة تسجيل الحضور

لا توجد كيانات بيانات جديدة أو تغييرات في مخطط قاعدة البيانات لهذه الميزة — تعديل عرض (UI) بحت على بيانات موجودة بالفعل.

## الكيانات الموجودة (بدون تعديل في بنيتها)

- **`Attendance`**: بلا تغيير — نفس الحقول (`studentId`, `date`, `status`) ونفس منطق `toggleAttendance`.
- **`Student`**: بلا تغيير — تُستخدم فقط للقراءة (`name`, `groupId`) عند بناء نص الشريحة والتصفية بالبحث.
- **`Group`**: بلا تغيير — تُستخدم فقط للقراءة (`name`, الجدولة) عند بناء شريط القفز بين المجموعات.

## حالة عرض جديدة (محلية فقط، غير مخزَّنة)

| الحالة | النوع | الوصف |
|---|---|---|
| `_searchQuery` | `String` | نص البحث الحالي داخل تبويب "تسجيل" — حالة UI محلية فقط، لا تُحفظ بين الجلسات، تُصفَّر عند تغيير اليوم أو إغلاق الشاشة. |

لا حاجة لأي حالة إضافية أخرى — شريط القفز بين المجموعات يعتمد على `todayGroups` المحسوبة بالفعل من `GroupController`/`AttendanceController`، بدون تخزين جديد.
